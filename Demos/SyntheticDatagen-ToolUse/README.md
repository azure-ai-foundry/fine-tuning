# Synthetic data generation for tool-calling fine-tuning

This demo fine-tunes a small model (`gpt-4.1-nano` or `gpt-4.1-mini`) to call a catalog of tools correctly, using **synthetic training data generated by the Foundry Data Generation API** from a static tool spec — no production agent traffic required.

## What it shows

End-to-end, with no manual data labeling:

1. **Convert** an OpenAI chat-completions tool catalog to OpenAPI 3.0 (the format the Foundry datagen API expects)
2. **Upload** the OpenAPI spec to your Foundry project
3. **Generate** ~50 training examples with the `ToolUseFineTuning` recipe (the service writes realistic user prompts + correct tool invocations)
4. **Submit** three fine-tuning candidates against the generated data (different model sizes / hyperparameters)
5. **Evaluate** each FT'd model on a held-out test split using **structural tool-call comparison** (tool name + arguments)
6. **Ship** the candidate that meets the lift threshold over the base model

## Result on the included tools

Using the Zava Post-Purchase Resolution Desk tool catalog (6 tools: order lookup, inventory, policy checks, resolution calculation, submit) and the autopilot's default lift threshold of +5%:

| Candidate | Base | Score (pass@8) | Lift |
|-----------|------|---------------|------|
| Baseline `gpt-4.1-mini` | — | 9.20 (100%) | — |
| Baseline `gpt-4.1-nano` | — | 8.74 (100%) | — |
| `conservative` | `gpt-4.1-nano` (3ep, lr=1.0) | 9.60 (100%) | **+9.8%** |
| `alt-mini` ← **shipped** | `gpt-4.1-mini` (3ep, lr=1.0) | **10.00** (100%) | **+8.7%** |

The fine-tuned `gpt-4.1-mini` matches the teacher's tool selection on every test row.

## Prerequisites

- An Azure AI Foundry project (`https://<resource>.services.ai.azure.com/api/projects/<project>`) with:
  - One **teacher** model deployment (e.g. `gpt-4.1` or `gpt-5.4`) for the datagen service to call
  - At least one **student** model deployment that supports fine-tuning (e.g. `gpt-4.1-nano`, `gpt-4.1-mini`)
- The `microsoft-foundry/fine-tuning` skill checked out locally — this notebook calls into its scripts
- Python 3.11+ with `openai>=2.0`, `azure-ai-projects>=2.2.0`, `azure-identity>=1.21`

## Run it

```bash
# Set your project endpoint + key
export AZURE_AI_PROJECT_ENDPOINT="https://<resource>.services.ai.azure.com/api/projects/<project>"
export AZURE_OPENAI_API_KEY="<key>"
export OPENAI_BASE_URL="https://<resource>.openai.azure.com/openai/v1"

# Point at the skill repo so the notebook can import its scripts
export FINETUNING_SKILL_PATH="/path/to/microsoft-foundry/fine-tuning/Skills"

jupyter notebook notebook.ipynb
```

The full run takes ~25-45 minutes depending on FT queue depth in your region.

## Bring your own tools

Replace `fixtures/zava_tools_openai.json` with your own tool catalog in the standard OpenAI chat-completions format:

```json
[
  {
    "type": "function",
    "function": {
      "name": "your_tool",
      "description": "What it does",
      "parameters": { ... JSON Schema ... }
    }
  }
]
```

The notebook will convert it to OpenAPI 3.0 automatically (via `generate_dataset.py --tools-from`).
